## Preferência de abordagem de estudo

O dono considera o formato padrão de cada fase do roadmap (teoria/checklist extenso primeiro,
prática só no fim) alongado demais. Para esta trilha, seguir esta ordem invertida dentro de
cada fase, sem pular nenhuma:

1. Ler primeiro o "🎯 Critério de conclusão" e a seção final "🛠️ Prática — Incremento do
   projeto" da fase — isso define o alvo concreto no projeto `sistema-academico`.
2. Ir direto para a prática/implementação.
3. Consultar os checklists de cada "Parte" **sob demanda**, só quando travar em um conceito —
   tratá-los como glossário de referência rápida, não como leitura sequencial obrigatória.
4. Priorizar as tabelas "Ponte De-Para" (Spring → Quarkus/Kotlin) como atalho, já que o dono
   vem de Spring.
5. Tratar as marcações ⭐/⭐⭐ como "provável causa se travar", não como "estudar antes de tudo".

Isso vale a partir da Fase 3 (Quarkus Core) em diante, onde o Quarkus aparece. Fases 0–1
(JVM/Gradle, Kotlin) continuam pré-requisito mínimo mesmo nesse formato mais prático.
